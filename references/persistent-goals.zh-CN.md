# 持久目标接入

仅在任务具备实施条件或恢复既有任务时读取。工具以当前会话暴露的名称、参数及说明为准；以下是支持这些工具的宿主中的接入方式，不承诺每个宿主都支持。

## 检查与创建

1. 检查可调用的目标工具。部分 Codex 宿主提供 `get_goal({})`、`create_goal({objective})`、`update_goal({status})`。分别核验创建、读回、恢复能力，并在 `STATE` 记录受支持的操作。能创建不代表能恢复：当前 `update_goal` 契约只允许 complete 或 blocked，不提供暂停或恢复；只使用当前宿主明确暴露并允许调用的恢复操作。可以经 `functions.exec` 调用 `tools.*`，不把 `functions` 当作可执行的 shell 命令。
2. 存在 `get_goal` 时先读取。当前任务已有未完成目标则核对并复用；目标停止时按下文恢复流程处理。若旧目标仅覆盖阶段或与最新任务契约不一致，记录差异，以 `STATE` 的完整契约推进已授权工作；没有受支持的编辑接口时不伪造完成以替换。另一个未完成目标不得覆盖；确需用户／宿主操作解除冲突时才提出具体所需动作。尊重用户暂停及预算／用量限制。
3. 从 `STATE` 生成自包含的目标文本：整体最终结果、全部重要验收项、必须遵守的约束、明确排除及禁止擅改范围、必要验证、整体停止条件、`STATE` 的绝对路径及专题／恢复入口。紧凑列出重要验收内容，细节链接原表；不只写“执行计划”或单一阶段。受宿主长度限制时压缩表达，不能删除实质要求。
4. 在用户显式调用本技能的上下文中直接调用 `create_goal`。本技能的调用约定及界面默认提示已明确请求自动建立目标；普通任务、仅阅读技能或创建／审查技能本身不能据此推断目标授权。只有用户明确给出 token 预算时才传 `token_budget`，不自行设定。
5. 创建后调用 `get_goal` 读回，确认返回的是本任务且状态为活动；将真实结果写入 `STATE`。调用超时或结果不确定先读回，避免重复创建。单有工具名称、配置开关或写下 `/goal` 文本不算已启动。
6. 创建成功并读回后立即执行当前未完成步骤；不存在额外的“启动按钮”工具时，不虚构第二次启动调用，不要求用户再发命令。

示例目标的内容结构（填真实信息后调用，非用户需手动填写的模板）：

```text
完成：{整体最终结果}。
验收：A1 {通过条件}；A2 {通过条件}；……。
约束与排除：{关键约束、兼容性、不得擅改的行为和本次授权边界}。
验证：{必要测试／构建／运行证据}。
仅当整体结果达成且所有必要验收有满足证据时完成；按适用 AGENTS.md 处理剩余工作和真实阻塞。
恢复：读取 {STATE 绝对路径及专题}、适用 AGENTS.md 和最新用户补充，核对实际状态后继续。
```

## 等待或中断后的恢复

收到已请求的信息、用户要求继续，或中断／压缩后恢复本任务时执行本流程。这是继续已经调用的任务，仅讨论技能本身不触发。

1. **重新判断原因。** 读取最新用户决定、`STATE` 及真实目标状态。区分外部信息缺失、用户明确暂停、预算／用量限制和宿主故障。记录哪项依赖已解除及其证据；资源已购买不代表接入成功，只解除输入和授权已经足够的步骤。保留尚未解决的依赖，清除已失效的整体阻塞原因。
2. **沿用已有授权。** 对因外部条件受阻的任务，用户补充已请求的信息即允许继续此前已授权的相关工作，不另要“恢复”口令、计划批准或再次调用技能。单纯补信息不覆盖用户要求保持暂停、取消任务或宿主限制。用户明确暂停须等其要求恢复；用量限制遵循宿主控制。状态询问或提及技能不解除这些限制。
3. **核对调度与工作进度。** 先通过上述授权及限制判断，再按下表处理。可恢复的停止状态包括因外部条件 blocked，以及用户已明确要求恢复的 paused。保留原目标身份及验收标准，记录当前恢复位置；阻塞审计按运行时恢复规则重新开始，不沿用旧计数。

| 宿主实际状态与能力 | 动作 |
| --- | --- |
| 同任务目标已 active | 清除旧阻塞记录，更新读回证据，执行下一个必要步骤；不重复建目标、不再要求恢复。 |
| 目标已获准恢复，且存在可用恢复操作 | 对原目标调用该操作，并读回目标身份及状态。确认 active 后执行下一个必要步骤；调用超时或结果不确定时先读回，再判断是否需要重试。即使调用返回成功，读回仍停止也不算恢复成功，按下一行处理。 |
| 已获准恢复的目标仍停止，且无可用恢复操作或恢复失败 | 工作可推进时记录为**目标待宿主恢复；当前会话执行中**。立即告诉用户自动目标接续尚未恢复、具体原因和受支持的恢复入口。支持该功能的 Codex 桌面宿主使用目标栏的“恢复”；仅在支持相应命令的入口使用 `/goal resume`。无需等待这次点击才继续已授权工作，但不能保证随后自动发起更多轮次。 |
| 读回失败或目标身份不符 | 标记目标状态未核验，保留最后已知状态和时间；调查不一致，不猜测 active、不修改别的目标、不盲目重复状态操作。只继续授权和归属仍明确的工作。 |
| 用户暂停、取消或未解除的宿主限制 | 保留限制及其恢复条件，不通过会话降级、新建目标或其他执行路径绕过。 |

4. **闭合恢复记录。** 在 `STATE` 保留工作进度、实际目标状态及时间、恢复能力、待处理动作和已发出的提示。首次恢复失败或发现状态不一致时就向用户说明，不等用户追问；调用结果不确定但紧接着在同轮读回核实时，合并一次说明即可，仍不确定则及时告知。同一提示已说明且条件未变，不在每次回复重复要求恢复，变化、新失败或用户询问时再说明。新读回确认 active 后清除待宿主恢复动作；仅凭用户说已恢复或恢复调用返回成功不算确认。
5. **只报告已观察的自动接续。** 聊天继续、修改 `STATE`、读回目标都不等于实际出现自动后续轮次。只有观察到宿主无需用户再催促就发起后续目标轮次，并执行必要工作，才记录自动接续已验证；否则保持未验证。这是调度证据，不是额外业务验收条件，不为取得它制造空轮或延迟已完成任务。

没有运行中的轮次时，技能自身无法发现外部环境已变化。记录后续信息或受支持的宿主事件如何触发重查，不保证无人通知时自动唤醒，也不在用户未要求时创建监控。

## 不可用或受限

先区分功能未启用、工具未暴露、调用失败、目标冲突与用户主动暂停。不能把产品文档中存在功能等同于当前会话可调用。

如本机存在 Codex CLI 且怀疑功能关闭，可用 `codex --version`、`codex features list` 只读检查。仅当确认为受支持的 `goals` 功能关闭、本次授权覆盖普通功能启用且宿主允许时，使用 `codex features enable goals`，保留其他配置，再核验。开关变成 true 不保证当前会话新增工具；不可为测试重启或中断用户工作。

无受支持的当前会话目标接口，或一次针对原因的正常修复后仍不能使用时，在 `STATE` 记录“无法自动启用持久目标”、检查与错误依据、已做的修复和“降级持续执行”模式，并向用户简短说明。按全局 AGENTS.md 继续当前可执行工作，保留完整状态和恢复入口；不得宣称已经进入目标模式或保证关闭应用后仍自动运行。

不通过修改 Codex 内部数据库、运行记录、向输入框注入命令或另建定时任务来伪造目标启动。用户主动暂停或预算限制不是技术故障，不以降级方式绕过。

## 完成与受阻

整体目标及全部必要验收满足，才调用当前工具支持的完成操作并读回。阶段结束、文档生成、单测通过或本地提交不代表目标完成。

`update_goal` 只能用于工具允许的状态；遵守它当场给出的真实阻塞判定、连续轮次阈值、预算和用户恢复约束。首次局部阻塞只记录状态并继续独立工作，不提前标记整个目标 blocked；达到工具要求的整体阻塞条件后如实标记。不为走完计数制造无意义轮次，也不为停止调用伪报 complete。

标记整体受阻前，将原因、影响步骤、所需解除证据、剩余独立工作和恢复位置保存在 `STATE`。说明整体未完成且自动接续将停止；若恢复依赖宿主控制，在同一次提示中说明该动作并记录已告知，信息到位后执行恢复流程。不为回避宿主恢复限制而把真正受阻的目标一直留在 active。

## 接口依据

目标功能的可用性由当前版本、宿主和会话决定。安装本技能不会自动让不存在的目标工具变为可用；每次以运行时核验为准。
